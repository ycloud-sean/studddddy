Day 2 FastAPI 学习笔记

今天从最基础的数据结构补起：list 和 dict 怎么配合，`values()` 为什么不能直接下标，`iter()` 和 `next()` 又是怎么工作的，然后把这些概念放回 FastAPI 的 GET / POST / PUT / DELETE 里。

主题：HTTP 方法 数据结构：list + dict 重点：状态码

今天的主线

1. 先懂数据 list 用来装一组数据，dict 用来描述一条数据，后面 Todo 的结构就是这两层叠起来。
2. 再懂方法 GET、POST、PUT、DELETE 分别对应查询、新增、更新、删除。
3. 最后懂响应 201 表示创建成功，204 表示删除成功但不返回内容，失败时用 HTTPException。

list 和 dict 关系

一个 Todo 通常是一个 dict，多个 Todo 放进 list 里。

todos = [
    {"id": 1, "title": "学习 FastAPI", "done": False},
    {"id": 2, "title": "练习 GET 接口", "done": False},
]

list 负责“装一组”，dict 负责“描述一条”。

你可以把 list 理解成书架，把 dict 理解成书架上的一本书。书架可以放很多本书，每本书有自己的标题、状态、编号。

dict 的三个常用视图

写法 作用 常见用法
todos.keys() 取所有 key 查看有哪些 id
todos.values() 取所有 value 拿到所有 Todo 对象
todos.items() 同时取 key 和 value 遍历时想同时拿 id 和 Todo 

todos = {
    1: {"id": 1, "title": "学习 FastAPI Day 2", "done": False}
}

print(todos.keys())
print(todos.values())
print(todos.items())

`values()` 为什么不能直接下标

todos.values() 返回的是 dict_values，不是 list，所以不能写 todo[0]。

todos = {
    1: {"id": 1, "title": "学习 FastAPI Day 2", "done": False}
}

todo = todos.values()
print(todo[0]["id"])  # 会报错
报错信息：TypeError: 'dict_values' object is not subscriptable。意思是这个对象不能用下标取值。

正确取法

方式 1：直接按 key 取 最推荐。知道 id 时直接写 todos[1]。
方式 2：遍历 values 适合处理所有 Todo，写 for todo in todos.values()。
方式 3：转成 list 如果一定要下标，先 list(todos.values())，再取 [0]。 
todo = todos[1]
print(todo["id"])

todo_list = list(todos.values())
print(todo_list[0]["id"])

for todo in todos.values():
    print(todo["title"])

`iter()` 和 `next()`

如果你想一个一个往后取，可以先把 values 变成迭代器。

iterator = iter(todos.values())
first_todo = next(iterator)
second_todo = next(iterator)

但学习阶段更直观的还是：

todo_list = list(todos.values())
first_todo = todo_list[0]
second_todo = todo_list[1]
记忆版：values() 能遍历，list(values()) 能下标，todos[id] 最推荐。

FastAPI Day 2 代码

你今天写的核心代码是一个内存版 Todo API。

from fastapi import FastAPI, HTTPException, Response, status

app = FastAPI()

todos = {
    1: {"id": 1, "title": "学习 FastAPI Day 2", "done": False}
}


@app.get("/todos")
async def get_todos():
    return {"data": list(todos.values())}


@app.get("/todos/{todo_id}")
async def get_todo(todo_id: int):
    if todo_id not in todos:
        raise HTTPException(status_code=404, detail="Todo not found")
    return todos[todo_id]


@app.post("/todos", status_code=status.HTTP_201_CREATED)
async def create_todo(title: str):
    todo_id = max(todos.keys()) + 1
    todos[todo_id] = {"id": todo_id, "title": title, "done": False}
    return todos[todo_id]


@app.put("/todos/{todo_id}")
async def update_todo(todo_id: int, title: str, done: bool = False):
    if todo_id not in todos:
        raise HTTPException(status_code=404, detail="Todo not found")
    todos[todo_id] = {"id": todo_id, "title": title, "done": done}
    return todos[todo_id]


@app.delete("/todos/{todo_id}", status_code=status.HTTP_204_NO_CONTENT)
async def delete_todo(todo_id: int):
    if todo_id not in todos:
        raise HTTPException(status_code=404, detail="Todo not found")
    del todos[todo_id]
    return Response(status_code=status.HTTP_204_NO_CONTENT)

状态码怎么理解

  • 200 OK：成功，通常还会返回数据。
  • 201 Created：创建成功，适合 POST 新增接口。
  • 204 No Content：删除成功，但不返回内容。
  • 404 Not Found：资源不存在。

status_code=status.HTTP_201_CREATED 管的是“成功时的默认状态码”。失败时你要自己 raise HTTPException。

今天最容易踩的坑

  • dict_values 不能直接下标。
  • DELETE 成功时如果不返回内容，用 204 更合适。
  • 查找某个 Todo 时，知道 key 就直接 todos[id]，比从 values() 里绕一圈更清楚。
  • title: str、done: bool 这种类型注解会影响参数校验。
