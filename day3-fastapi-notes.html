Day 3 FastAPI 学习笔记

今天只抓一件事：接口怎么接收输入。重点是路径参数、查询参数、类型注解，以及 Annotated、Path、Query 各自负责什么。

主题：参数接收 代码：my_day03/main.py 接口：GET /products 接口：GET /products/{product_id}

今天结论

路径参数 由 URL 路径里的 {} 决定，例如 /products/{product_id}。
查询参数 函数参数没有出现在路径里时，FastAPI 通常会把它当成查询参数。
Annotated 负责把类型、校验规则、接口文档说明写得更清楚。
一句话记法：/products/{product_id} 决定 product_id 从路径来，Query(...) 和 Path(...) 主要负责补充规则、校验和文档说明。

两个接口怎么分工

接口 作用 参数来源 适合场景
GET /products 查询商品列表 ?q=鼠标&category=键鼠 搜索、筛选、分页、排序
GET /products/{product_id} 查询单个商品详情 /products/1 通过唯一 ID 找一个资源

路径参数

路径参数是 URL 路径本身的一部分，通常表示“我要找哪一个资源”。

@app.get("/products/{product_id}")
async def get_product(
    product_id: Annotated[
        int,
        Path(gt=0, description="商品 ID，必须大于 0"),
    ],
):
    product = products.get(product_id)
路径模板

/products/{product_id}

对应
函数参数名

product_id

Path(gt=0) 的意思是：这个参数来自路径，并且必须大于 0。真正让它成为路径参数的关键，是路径里写了 {product_id}。

查询参数

查询参数写在 ? 后面，通常表示“我要怎么查”。

GET /products?q=鼠标&category=键鼠&in_stock=true

对应代码：

@app.get("/products")
async def list_products(
    q: Annotated[
        Optional[str],
        Query(description="按商品名称关键字搜索"),
    ] = None,
    category: Annotated[
        Optional[str],
        Query(description="按商品分类筛选"),
    ] = None,
):
/products 路径里没有 {q}、{category}，所以这些函数参数会作为查询参数接收。

Annotated 怎么读

Annotated 可以理解成“类型 + 额外说明”。

写法 类型含义 额外规则 默认值
Annotated[Optional[str], Query(...)] = None 字符串，或者不传 作为查询参数，并生成文档说明 不传时是 None
Annotated[float, Query(ge=0)] = 0 数字 必须大于或等于 0 不传时是 0
Annotated[int, Query(ge=1, le=20)] = 20 整数 范围是 1 到 20 不传时是 20
Annotated[int, Path(gt=0)] 整数 路径参数，必须大于 0 路径参数必须传

Day 3 参数清单

参数 来源 类型 作用 示例
q Query Optional[str] 按商品名称关键字搜索 /products?q=鼠标
category Query Optional[str] 按商品分类筛选 /products?category=键鼠
min_price Query float 最低价格 /products?min_price=200
max_price Query float 最高价格 /products?max_price=500
in_stock Query Optional[bool] 是否只筛选有库存商品 /products?in_stock=true
limit Query int 最多返回多少条 /products?limit=2
product_id Path int 查询某个商品详情 /products/1

列表接口过滤顺序

list_products 的核心逻辑是：先拿全部商品，再一层一层按条件筛掉不符合的商品。

  1. 用 list(products.values()) 拿到所有商品。
  2. 如果传了 q，就按名称关键字筛选。
  3. 如果传了 category，就按分类筛选。
  4. 如果传了 in_stock，就按库存状态筛选。
  5. 最后按 min_price 和 max_price 筛价格。
  6. 返回时用 result[:limit] 控制最多返回多少条。
result = list(products.values())

if q:
    result = [
        product
        for product in result
        if q.lower() in product["name"].lower()
    ]

return {
    "count": len(result),
    "items": result[:limit],
}

类型注解帮你做什么

自动类型转换 /products?limit=2 里的 2 原本是字符串，但 FastAPI 会按 int 转成整数。
自动参数校验 Query(ge=1, le=20) 会限制 limit 只能在 1 到 20 之间。
URL 里所有内容本质上都是文本。你写的 int、float、bool 会告诉 FastAPI 应该怎么解析这些文本。

可以这样测试

测试目标 请求 预期结果
查全部商品 GET /products 返回 4 个商品，count 是 4。
按关键字查 GET /products?q=鼠标 只返回名称里包含“鼠标”的商品。
按分类查 GET /products?category=键鼠 只返回分类是“键鼠”的商品。
按价格查 GET /products?min_price=200&max_price=500 只返回价格在 200 到 500 之间的商品。
按库存查 GET /products?in_stock=true 只返回有库存的商品。
查商品详情 GET /products/1 返回 id=1 的商品。
查不存在商品 GET /products/999 返回 404，提示“商品不存在”。

常见坑

把 ID 放进查询参数 详情接口更常见写法是 /products/1，不是 /products?product_id=1。
忘记默认值 想让查询参数可选，就要写类似 = None 或 = 20 的默认值。
误解 Query 和 Path Query、Path 不只是“分类标签”，它们还会影响校验和接口文档。

今天必须会说清楚

  • product_id 是路径参数，因为路径写了 /products/{product_id}。
  • q、category、limit 是查询参数，因为它们是 /products 的筛选条件。
  • Path(gt=0) 表示路径参数必须大于 0。
  • Query(ge=1, le=20) 表示查询参数有范围限制。
  • Optional[str] = None 表示这个参数可以不传。
