Day 4 FastAPI 学习笔记

今天学习 Request Body 和 Pydantic 模型。Day 3 让接口能从 URL 接收输入，Day 4 让接口能从 JSON 请求体接收一整个对象。

主题：Request Body 模型：Pydantic BaseModel 代码：my_day04/main.py 接口：POST /products

今天结论

请求体放复杂对象 创建商品时要传名称、分类、价格、库存等字段，这种一整块数据适合放在 JSON body。
Pydantic 定义结构 ProductCreate 告诉 FastAPI 请求体应该长什么样。
Field 定义规则 Field(gt=0)、Field(max_length=50) 负责字段校验和文档说明。
一句话记法：函数参数如果是 Pydantic 模型，比如 product: ProductCreate，FastAPI 会默认从请求体里读取 JSON。

三种参数来源

类型 从哪里来 适合放什么 例子
Path URL 路径 唯一资源 ID /products/1
Query ? 后面 搜索、筛选、分页 /products?q=鼠标&limit=2
Body HTTP 请求体 复杂对象 {"name": "人体工学椅", "price": 899}

请求体长什么样

创建商品时，客户端发送的是一段 JSON。它不在 URL 里，而是在请求体里。

{
  "name": "人体工学椅",
  "category": "办公",
  "price": 899.0,
  "in_stock": true,
  "description": "适合长时间学习和办公"
}
查询参数适合短小条件，请求体适合结构化数据。创建商品、提交表单、更新资料这类场景，通常都会用请求体。

Pydantic 模型

BaseModel 定义了请求体的数据结构，Field 定义每个字段的规则。

class ProductCreate(BaseModel):
    name: Annotated[
        str,
        Field(min_length=1, max_length=50, description="商品名称"),
    ]
    category: Annotated[
        str,
        Field(min_length=1, max_length=30, description="商品分类"),
    ]
    price: Annotated[
        float,
        Field(gt=0, description="商品价格，必须大于 0"),
    ]
    in_stock: Annotated[
        bool,
        Field(description="是否有库存"),
    ] = True
    description: Annotated[
        Optional[str],
        Field(max_length=200, description="商品描述"),
    ] = None
没有默认值的字段是必填，例如 name、category、price。有默认值的字段可以不传，例如 in_stock 和 description。

字段规则怎么读

字段 类型 规则 是否必填
name str 1 到 50 个字符 必填
category str 1 到 30 个字符 必填
price float 必须大于 0 必填
in_stock bool 默认是 true 可选
description Optional[str] 最多 200 个字符 可选

创建商品接口

Day 4 新增的是 POST /products。它用请求体创建一个商品，并返回 201 Created。

@app.post("/products", status_code=status.HTTP_201_CREATED)
async def create_product(product: ProductCreate):
    product_id = max(products.keys(), default=0) + 1
    new_product = {
        "id": product_id,
        **product.model_dump(),
    }

    products[product_id] = new_product

    return {
        "message": "商品创建成功",
        "data": new_product,
    }
product: ProductCreate 是核心。FastAPI 会读取 JSON 请求体，把它校验成 ProductCreate 对象，再传给函数。

model_dump 怎么理解

product 是 Pydantic 模型对象，不是普通字典。保存到内存字典之前，先用 model_dump() 转成普通字典。

product.model_dump()

再用 ** 把字段展开进新字典：

new_product = {
    "id": product_id,
    **product.model_dump(),
}
记忆版：model_dump() 把模型变字典，** 把字典里的键值对展开。

故意传错看看

少传必填字段 不传 category，FastAPI 会返回 422。
价格不合法 price 传 0 或负数，会被 Field(gt=0) 拦住。
字符串太长 name 超过 50 个字符，会被 max_length=50 拦住。
422 Unprocessable Entity 在这里通常表示：请求格式是 JSON，但里面的数据不符合模型规则。

Path、Query、Field 区别

工具 用在哪里 负责什么 例子
Path 路径参数 校验 URL 路径里的参数 Path(gt=0)
Query 查询参数 校验 ? 后面的参数 Query(ge=1, le=20)
Field Pydantic 模型字段 校验 JSON body 里的字段 Field(min_length=1)

今天必须会说清楚

  • POST /products 用来创建商品，所以使用请求体接收商品对象。
  • ProductCreate 是 Pydantic 模型，负责描述请求体结构。
  • Field 可以给字段加长度、范围和文档说明。
  • 没有默认值的模型字段是必填，有默认值的字段是可选。
  • product.model_dump() 可以把 Pydantic 模型转成普通字典。
  • 请求体校验失败时，FastAPI 通常返回 422。
